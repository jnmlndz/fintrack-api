# FinTrack API

Backend for **FinTrack**, a personal finance dashboard. Built as a portfolio project to practice real backend architecture: secure authentication, resource-based authorization, and reporting with aggregate queries.

🔗 Frontend of this project: [fintrack-web](https://github.com/jnmlndz/fintrack-web)

## Stack

- **NestJS** — backend framework with modular architecture
- **TypeORM** — ORM (Object-Relational Mapping) for MySQL
- **MySQL** — relational database
- **JWT (JSON Web Token)** + **Passport** — authentication
- **bcrypt** — password hashing
- **class-validator** — input validation

## Features

- Registration and login with hashed passwords (bcrypt) and JWT tokens
- Protected routes using Passport Guards and Strategies
- Full transactions CRUD with **resource-based authorization** (each user can only access their own data)
- Financial reporting endpoints built with TypeORM's Query Builder:
  - Overall balance (total income, total expenses, net balance)
  - Expenses grouped by category
  - Monthly summary (income vs. expenses per month)
- Strict input validation (whitelist + forbidNonWhitelisted) to reject unexpected fields

## Running it locally

1. Clone the repo and install dependencies:

```bash
npm install
```

2. Create a `.env` file in the root with:

```env
DB_HOST=localhost
DB_PORT=3306
DB_USERNAME=root
DB_PASSWORD=your_password
DB_NAME=fintrack_db
JWT_SECRET=a_long_random_secret
JWT_EXPIRES_IN=1h
```

3. Create the database in MySQL:

```sql
CREATE DATABASE fintrack_db;
```

4. Start the server:

```bash
npm run start:dev
```

The API runs on `http://localhost:3000`. Tables are auto-generated by TypeORM in development mode.

## Notable technical decisions

- **Resource-based authorization**: every operation on a transaction checks that `userId` matches the token owner, not just that the user is authenticated — this prevents a user from accessing another user's data even by guessing an ID.
- **Amounts stored as `decimal`, never `float`**: avoids precision errors in financial calculations.
- **Generic error messages on login** ("invalid credentials" for both a nonexistent email and a wrong password): avoids leaking which emails are registered.
- **Aggregate queries via Query Builder**: reports use `SUM`, `GROUP BY`, and `DATE_FORMAT` directly in SQL through TypeORM, instead of fetching every row and calculating in JavaScript — more efficient at scale.
